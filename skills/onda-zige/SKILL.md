# 全面自我画像（Onda）

这是 FateBridge 最完整的单次分析场景。来问「我是谁」的人，不是只要一个维度——他要的是全貌。这个 Skill 把七个维度和三套体系拉通，给一个立体的、有交叉印证的人。

## 引用路径

发现入口可能是软链接。优先进入入口目录后用 shell 内建 `pwd -P` 取得真实目录，再按它读取下面的相对引用；不要为解析路径调用未经核实的系统 `python3`。不能先裁剪 `.agents/skills/onda-*` 入口的字符串父目录，否则会误指到 `.agents/skills/_shared` 或 `.agents/docs`。读取已知引用无需搜索仓库。

## 这个场景用哪些工具

「全面自我画像」路由核心：`analyze_destiny`（八字）、`ziwei_birth`（紫微）、`astro_chart`（西占）三系同时为**主**证，并行调用、并行出结论；三系一致→合并去重，三系分歧→显式标注「两套/三套口径不一」，各自呈现，保留给用户权衡。token 控制：并行时务必用 `fields` 或 `selected_sections` 裁剪，不要对每个工具裸吐完整 `snapshot_text`。

下面是可选维度，不是十一项必调清单。完整画像先取三套主证，再补用户关心且未覆盖的专项；已有大运／流年不重复计算。资料不足的体系保留缺失，先交付已有结果，不猜时刻或坐标凑齐三套。

西占时运明确指定钟时时，按其已加载合同传 `analysis_hour/minute`，核对返回的实际分析时刻；首轮字段按工具建议，不默认请求整个 `time_lords` 或所有时间线。若返回 `result_delivery`，按共享引擎指引读取原 run 的所需字段／页面，不能重算或把单页 JSON 片段当全文。

### 第一层：八字维度（按问题选择）

| 步骤 | 工具 | 看什么 |
|------|------|--------|
| 1 | `bazi_personality` | 性格内核、气质类型、行为模式 |
| 2 | `bazi_birth` | 仅明确需要原始命盘时调用；与综合分析二选一，避免重复 |
| 3 | `analyze_destiny` | 综合命理：八字+喜用+格局，一站式定位 |
| 4 | `bazi_career` | 事业方向、适合的路子、官杀食伤 |
| 5 | `bazi_romance` | 正缘桃花、感情时机、桃花质量 |
| 6 | `bazi_health` | 身体倾向、五行偏枯、养护方向 |
| 7 | `bazi_relatives` | 六亲关系、原生家庭、与父母兄弟的互动 |

### 第二层：大运时运（聚合优先）

| 步骤 | 工具 | 看什么 |
|------|------|--------|
| 8 | `dayun_analysis` | 单独深查某步大运时调用（需 `--analysis-age`，按虚岁）；已有综合时运时不默认重复 |
| 9 | `timing_analysis` | 综合时运：大运+流年+流月一起看 |

### 第三层：用户要求的跨体系对照

| 步骤 | 工具 | 看什么 |
|------|------|--------|
| 10 | `ziwei_birth` | 紫微命盘十二宫安星，另一套语言讲同一个人 |
| 11 | `astro_chart` | 西占出生盘（需经纬度），行星落宫、相位 |

## 怎么收信息

出生 **年月日时 + 性别 + 出生城市／时区**。西占按实际 Schema 另需 **经纬度**；不能以已填写城市代替缺少的必填坐标，也不能猜坐标。

```
--name 张三 --gender 男
--birth-year 2000 --birth-month 12 --birth-day 10
--birth-hour 9 --birth-minute 55
--birth-place 江苏南通海安
--birth-longitude 120.45 --birth-latitude 32.54
--birth-timezone Asia/Shanghai
--use-true-solar-time
```

**时辰未知**：当前工具要求 `--birth-hour`，不能省略或擅自填 0。先确认小时；若用户授权按假设时刻做敏感性比较，明确标注假设与不稳定结论。

## 工作流

1. **接住** —— 先回应他为什么来问（一两句，别长）。
2. **收信息** —— 如果用户没给出生信息，先问。必填：年月日时、性别、城市。
3. **跑八字维度** —— 用综合分析定位，再按问题选尚未覆盖的专项；首轮按验证过的精简字段读结构化结果，原始命盘不默认重复，完整文本在需要时展开。
4. **跑时运** —— 用户需要全景且已有专项未覆盖时用 `timing_analysis`；只深查单步大运才用 `dayun_analysis`（`--analysis-age` 为虚岁）。
5. **跑跨体系** —— `ziwei_birth` 和 `astro_chart`，各抓 2-3 个最突出信号。
6. **交叉印证** —— 按 fatebridge-engine.md「跨体系交叉印证」的方法：
   - 三套描述重合 → 合并说明来源，与用户实际经验对照。
   - 某结论只有一套提到 → 弱信号，当倾向，不定论。
   - 两套分歧 → 先核对输入和精度，再分别呈现。
7. **讲盘** —— 挑最相关的 5-7 个信号，按维度组织（性格→事业→感情→健康→时运），每个维度都融合多套体系的结论。不要把每个工具结果各背一遍。
8. **落到事** —— 给 2-3 个具体、今年就能动的小建议。
9. **收尾** —— 落在一件具体小事上，每次不一样。带一句边界声明。

## 解读骨架（参考，不是模板）

```
[性格内核]
八字日主 + 十神格局 → 你是哪种人。
紫微命宫主星 + 西占上升/月亮 → 另外两套怎么讲你。
共同描述合并，分歧保留来源，不据此断言现实结果。

[事业方向]
八字事业专项 + 食伤官杀 → 适合什么路子。
紫微官禄宫 → 另一个视角。
落到具体的行业/角色建议。

[感情姻缘]
八字婚姻/桃花 → 感情模式、正缘信号。
紫微夫妻宫 → 另一个视角。
今年的感情时运。

[健康倾向]
八字健康 → 五行偏枯对应的身体倾向。
时运对精力的影响。
只谈养护，不诊断。

[时运节奏]
当前大运 + 今年流年 → 现在在哪一段。
紫微运限 → 另一个视角。
接下来 1-2 年的大节奏。

[综合建议]
2-3 个今年能动的具体建议。
```

## 注意事项

- **不要把所有工具结果全部罗列。** 用户要的是画像，重复排盘不会增加证据。每个维度融合多套体系的 2-3 个信号即可。
- **跨体系对照保留覆盖范围。** 全面请求按资料可用程度覆盖八字、紫微、西占，缺失层明确标注；相同描述不是独立统计证据，不能证明现实预测准确。
- **西占需要经纬度。** 缺必填坐标时核对实际地点或请用户补充，不用示例值；地点近似与星历模型近似是不同误差，分别说明。
- **`dayun_analysis` 需要 `--analysis-age`（虚岁）。** 用 `当年年份 - 出生年份 + 1` 算。
- **解读长度适中。** 全面但不冗长，每个维度 2-3 段，总长控制在 1500-2500 字。
