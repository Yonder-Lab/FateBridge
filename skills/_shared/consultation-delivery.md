# 按问题组织结果

需要对照、时间线或较完整的解释时读取。这里是交付选择，不是每次都要填满的模板；场景 skill 的证据范围优先。

## 选择最有用的形态

| 用户想看清什么 | 有实际依据时交付 | 需要保留的区别 |
| --- | --- | --- |
| 一个具体问题 | 一句回应 + 2–3 个本次依据 + 一项现实建议 | 计算值、传统解释、现实建议 |
| 术语、方法原理或已有结果的含义 | 用核对过的来源解释含义、适用条件及与问题的联系 | 不为讲概念索要生辰；有来源解释不冒称新增个案计算 |
| 所选计算缺资料且用户无法补充 | 先交付可答部分，具体说明能继续的解释或适用替代路线 | 不反复索取同项，不猜必填值，不伪造无时盘 |
| 两个岗位／两种做法 | 已知职责／条件的短对照，指出仍须核实什么 | 岗位条件来自用户；盘只提供文化视角，不生成 offer 胜率 |
| 两人相处 | 共同点与差异各一项，联系一件可沟通的事 | 双人关系结果与各自内部结构；未知对方心意 |
| 一段时间如何安排 | 仅列实际返回的阶段／边界／变化及可参考范围 | 本命背景、大运、年、月、日；不把长周期细化成吉日 |
| 性格／学习方式 | 一项特点、一项适用条件、一项可自行核对的经验 | 传统描述与用户实际能力；无需把描述全部认领 |
| 三体系全面画像 | 按用户关心的主题对照来源、重合、分歧和缺失 | 多体系共享输入，一致不是独立证据；不补缺失维度 |
| 星盘／卦盘 | 先给关键盘面或卦变，再讲与问题有关的含义 | 盘式、参数、时间和真实返回；不由流派名扩大支持范围 |
| 空间／物件 | 逐对象讲已有判断、适用条件和未覆盖项 | 事实与照片候选；解释与行动 ready。细则以风水交付参考为准 |
| 健康文化 | 解释传统对应，再给独立的现实生活观察建议 | 传统标签不成为疾病、器官功能或心理状态判断 |

有依据的比较要说明更倾向哪个及理由、适用条件和主要取舍；没有高下时再如实说明，不强求双方各占一半。空建议列表、缺失时机和规则冲突也要解释具体影响：缺失仅约束相关结论，已知部分照常交付，不为表格完整而编答案。引擎未生成建议文案，不妨碍助手给出注明实际理由的现实建议。

## 从证据到表达

以下为虚构的表达练习，条件不满足就不使用；不是某个出生日期的实测结论。

**给定条件：** 事业结果同时有偏表达输出的职业类型与创业约束；用户已说在比较方案沟通岗和流程执行岗。

可写：「这次事业分析里，表达输出比按既定流程执行更突出；但创业部分还有约束，不能一起理解成适合马上单干。放到你说的两个岗位，可以重点核对方案岗是否真的有需求访谈和方案讲解，而不只看岗位名字。这是结合传统描述的现实筛选建议，最终还要看职责、收入和团队。」

**给定条件：** 两人的关系结果有一个互补项与一个磨合项，用户问合作分工。

可写：「本次双人结果同时保留了互补和磨合，整体分数不能替代分工讨论。可以把返回的两个具体项分别说明，再和你们已给的职责对照；没有返回某个人的沟通习惯，就不替他补一种性格。实际先确认一项争议任务由谁决定，比据分数判断能否长期合作更有用。」

真实答复用本次实际项目替换这里的条件描述；不能把示例里不存在的结论当成计算结果。

## 展开和复用

- 用户追问「为什么」：从同一 run 读取对应依据，解释作用范围，不把全部原始 JSON 倒进聊天。
- 用户追问术语或传统理由：结合已得事实与核对过的来源展开；讲清为什么与本题有关，不只复述状态、触发规则和不能下的结论。同一主题事实与范围未变，不重复参考边界。
- 用户追问「还有呢」：先展开已保留结果；只有新维度、新体系或新时点才增加计算。保留 trace／parent 关系。
- 用户更正出生时刻／现场事实：只重建受影响部分，说明哪些判断改变、哪些仍有依据；不能为了保持前文一致而忽略新事实。
- 用户一开始要完整 JSON／全文文件：首次 `fields=null`，从同一 run 交付并核对散列；简答规则不裁剪全文。

写完检查：用户能否说出本次判断、至少一条为什么，以及建议适用的条件？个案解读去掉名字后若仍适用于几乎所有人，回到实际字段和问题找出差异；找不到就缩小结论，不靠编故事制造个性化。纯概念回答则检查含义、例子和来源是否讲清，无需虚构个性化。
