# Codex 用户体验修复记录

2026-10-12 在本地工作区，以虚构资料完成 CLI、独立 stdio MCP 与进程内 REST 的使用走查。接入方式见 [Codex 使用指南](codex-guide.md)，原始证据见 [体验报告 JSON](audits/2026-10-12/codex-experience/report.json)，人工对话解读见 [对话走查](audits/2026-10-12/codex-experience/dialogue-walkthrough.md)。

## 发现与修复

| 体验障碍 | 复现 | 修复后的行为 |
| --- | --- | --- |
| Codex 接入格式不清楚 | 接入指南只给其他 host 的 `mcpServers` JSON | 新增 Codex 原生 TOML、注册命令和连接确认步骤 |
| 不知道装对了没有 | 缺少统一的解释器、依赖和 MCP 检查入口 | `doctor` 输出当前绝对路径与配置；`--mcp` 从无关目录启动独立进程并计算一条虚构输入 |
| 用户问题搜不到工具 | `discover --query 跳槽` 返回 0 项 | 搜索复用场景触发词和路由词，同时保持分类、端与可见集合筛选 |
| 名称映射容易踩坑 | `describe astro_hellen` 报未知工具 | CLI、发现和资源接受 key / 公开名；返回正式 `cli_name`，MCP call 仍用实际发布名 |
| 示例复制后不能运行 | 原 `cli_example` 含 `<int>` 等占位符 | `cli_usage` 明确是模板；27 个工具有已校验的虚构输入与可执行示例 |
| 一次 describe 太大 | 默认包含完整输入和专业输出 Schema | 增加 `--detail input`，仍可按需读取完整输出契约 |
| 默认 MCP 工具负担较大 | 87 工具的完整 Schema 约 4.3 MB | Codex 指南与 doctor 显式支持场景选择；事业场景只公开 7 项，约 289 KB |
| 综合命盘不能控制输出 | profile 没有 `fields`、compact 等开关 | 支持完整复合路径的裁剪、严格校验、紧凑输出和各子结果快照开关 |
| 空 profile 被当成功 | `--systems ',,'` 输出空 profile，退出 0 | 至少要求一个体系，返回明确用法错误 |
| 同一命盘重复算 | `--systems bazi,八字` 调用同一工具两次 | 按实际工具去重，保留第一个用户标签 |
| 复合投影可能掩盖失败 | 新的 profile 投影需要处理部分成功 | 所有失败项仍保留，退出 1；所选子结果保留完整 receipt |
| metadata 开关位置不自然 | 单工具后加 `--no-metadata` 报用法错 | 工具命令前后均接受该开关 |
| 合盘摘要重复且丢信息 | 相同挑战占据一个维度的两个摘要位置 | 先取不同摘要，再跨维度去重；完整事件与数值权重保留 |
| 解读文字有重复前缀 | 梅花/卦义文字出现“忌忌” | 修复共享拼接，覆盖卦义查询、梅花与六爻；保留原始 caution 文本 |
| 初始化说明不指导工作流 | instructions 只列领域，未指导发现、取数、裁剪、判错 | 给出资源入口、主证/旁证规则、缺时处理、严格投影、原生错误与精度边界 |

## 实际验证

独立 stdio 进程在临时工作目录中运行，验证八字、事业、时运、紫微、核心星盘、希腊盘、双人关系、梅花、六爻、奇门、基础风水方位和知识读取共 12 类调用。每项检查公开输出 Schema，以及同输入裁剪前后的业务摘要一致。

事业示例从 约 15.6 KB 缩到约 2.6 KB，保留事业类型、时机信号、分析日期和完整运行凭据。综合 CLI 示例保留八字日主和星盘精度，两体系共约 4.9 KB。工具列表按事业场景缩小约 93%，这来自服务器实际注册范围变化，完整全量列表仍较大。

4 类错误在原生 MCP 中使用 `isError=true` 并带安全字段路径；修正后同一连接恢复成功。REST 同类非法日期返回 422，修正后返回 200。Codex CLI 用单次配置覆盖成功解析了 stdio 配置，未写入全局设置。

已构建 wheel，将其安装到仓库外的临时位置，确认加载路径来自该 wheel，并通过独立 stdio doctor 检查。完整依赖使用现有虚拟环境，未将此检查称为全新操作系统的安装验证。

四份 golden 基线仅迁移了展示前缀和合盘摘要，迁移脚本核对每一个数值叶子完全不变。原始事件、柱位、合盘评分和排盘算法未因此改动。参考环境的完整 golden 字节比较仍需 Linux x86_64 / Python 3.12；本地 macOS 跳过这组比较。

固定最新源码的完整回归为 1,917 项通过、89 项跳过、0 项失败，其中 20 项覆盖本轮新增的体验检查。mypy、Black、isort 和 diff 检查通过；FastMCP 3.0.0 的独立接入检查也通过，其他依赖仍使用当前虚拟环境，未把它称为完整最低依赖组合验证。

最终测试与源码快照记录在 [validation.json](audits/2026-10-12/codex-experience/validation.json)。完成时校验副本与工作区的 291 份 Python 源文件一致。同目录还有其他结构整理工作，本记录只归属上述体验改动；不把共享工作区的其他差异记作本轮修复。

## 验证边界

这是当前助手的真实工具调用与人工解读走查，不是另一位 LLM 的自动对话评测。没有创建新 Codex 聊天，没有修改全局 MCP 配置，没有验证当前聊天加载后的 MCP 工具选择，也没有远程部署或发布。本聊天可立即使用已安装的 CLI；正式 MCP 对话按指南注册并确认连接后进行。

核心星盘使用哪种星历仍取决于实际环境；无时盘、完整地理编码和未实现住宅层依然是已知能力边界。指南明确了这些场景怎样补信息、保留缺口与解释 `partial`。
