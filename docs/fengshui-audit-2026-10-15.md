# 工位与家居风水算法、工具及技能审查

本轮依据方法调研审查真实源代码、规则数据、请求/输出模型、REST/MCP/CLI、投影、场景目录与 onda-fengshui。重点是补齐通用的事实—计算—行动链路，不要求某个案例得出特定摆法，不新增没有完整来源和输入依据的吉凶规则。

## 审查结论

| 层 | 已有能力与本轮结论 |
| --- | --- |
| 公共方向 | 后天八卦、八方与24山角区；坐向分开，北参考显式，不自动识别户型或立极 |
| 八宅 | 选定坐山版本、个人命卦、用途关系与多人集合；不是完整独立《阳宅三要》结构实现 |
| 金锁 | 有版本的八宫基础砂水偏好；未覆盖完整24山形态与元运，不可据名称自动归类 |
| 年星 | 立春年度边界与逐宫飞布；保持独立，不能替代历史宅盘 |
| 玄空 | 明确定运依据、磁北、下/替卦、山界候选、运山向角色；合并后另有显式有限五行、当令及外局存在条件解释，尚无完整星组合与外局质量判定 |
| 室内形态 | 署名现代作者规则，入口、直线、背靠等独立；不等于所有古典形势 |
| 桌面 | 显式现代BTB作者法，近远左右与罗盘独立；保留无规则物件 |

复核了命卦纪元/寄宫、大游年异或、灶位/火门用途分离、年星入中与顺飞、玄空定运/三元龙/替星/分界候选的实际路径。未发现需要通过本次新增流派口诀纠正的计算依据。相关独立参考、边界与跨传输回归及Linux golden应与本轮变更一起验证，不能以过去绿灯替代本轮证据。

## 根因与通用修复

1. **方法默认与场景不匹配。** 旧聚合默认三法，纯形态/桌面容易收到无关缺失项。新增显式workstation/home场景，按已给事实选法；显式methods优先；独立形态/桌面也采用这一逻辑。无场景、无作者输入的旧原始请求保持兼容。
2. **家具缺乏机器可读动作约束。** 桌面已有许可与空间合同，门床桌灶却只有方向候选和通用待确认。新增layout_constraints，把搬位、转向、新增分别记录；禁止动作阻止相应建议且不继续追其许可，计算关系仍保留。桌面与家具新增许可不能矛盾。
3. **没有独立候选方案的完整评估链。** 新增layout_alternatives，对用户提出的方案重算同一套规则。保持对象用途、使用人集合、位置/朝向维度；搬转后不继承旧形态。原先检查过的走道、梁、尖角或朝向也不能在候选中省略后获ready。
4. **可执行性易被当作吉凶胜负。** 许可、实际可行性、规则计算完整性分别判定；ready仅为执行门槛，逐规则匹配与权衡继续保留。不加流派权重、不平均评分、不自动选赢家。可选候选未确认不重新打开现状事实审查。
5. **完整家居能力边界不够显著。** scene_scope与unsupported_queries及技能明确列出独立阳宅三要、完整古典形势、三合、大卦、自动几何与完整玄空组合解释的未覆盖状态。已排盘或已审查所交对象，不能表述成全宅审查完成。
6. **照片镜面候选与新增许可。** 照片产生的镜面方案保持candidate_only；禁止新增时相关动作blocked。候选首次引入的作者规则会进入顶层rulesets/rule_trace，避免动作有rule_id却没有来源。
7. **传输默认值会抹去“省略”语义。** 三端自动选法回归发现MCP先物化旧三法默认，REST却能按事实选层。公开methods改为null自动哨兵，统一模型再归一化；显式列表优先，旧无场景无作者请求实际仍选三法。保留自动与显式两类真实三端测试。

8. **节气回退的防护路径不一致。** 原先日期命卦及跨运玄空已有保守处理，年度飞星与带时区出生时刻仍可在近似立春附近给唯一年。共享历法现在标明有效年待确认及相邻年候选，年盘不飞唯一盘、命卦不生唯一候选；显式有效年及远离边界的时刻仍可用。保守范围沿用既有相邻公历日策略，是求解器不确定性策略，不是风水距离或吉凶规则。

新增的layout_feasibility_v1是工程筛选策略，不是传统规则集。原有传统规则数据、作者规则和golden文件没有针对案例改写。

## 对外合同与技能

共享请求模型驱动三个传输；输出声明新增候选分支。工具描述与call_guidance说明场景、许可、新观察及ready含义；AGENTS.md生成区与场景manifest由脚本再生。onda-fengshui与咨询闭环增加工位/家居选法、候选比较、输入保存、未覆盖家居方法及执行边界。

完整字段、来源和不支持项目见[场景与候选合同](fengshui-scene-planning.md)。示例为[固定工位](examples/fengshui-workstation-planning.json)和[家居候选](examples/fengshui-home-alternatives.json)，均为合成资料。

## 验收口径

新增测试覆盖四用途、八方向、许可/可行性组合、独立重算、来源、旧形态隔离、禁止省略不利维度、身份/用途/使用人校验、跨层新增约束与真实REST/MCP/CLI输入输出。测试期待来自独立请求、合同不变量与已有参考规则，不来自某个用户案例的“应有摆法”。

最终环境、冻结源码散列、全仓测试和Linux golden结果见[验收记录](audits/2026-10-15/fengshui-scene-validation.json)。本轮软件验收不包含新建Desktop会话中的真实模型咨询、现场搬转后的复核或现实运势效果。原工作区既有改动预先备份并在最终按路径/散列核对；未自动提交或推送。

## 合并版本最终验收

按用户确认，将本轮场景、动作约束、候选重算及历法修复，与并行聊天“启动 Agent Team 补充”完成的有限玄空解释层一起验收。最终冻结730文件，清单SHA-256为`48501d76573af403ec71192b933bbb8bb357595dc3ded4357003675024458f60`；以下结果全部对应同一份合并源码。

- Linux x86_64／Python 3.12：全仓 **2780通过、0跳过、0失败**；源码只读挂载。
- macOS arm64／Python 3.13：全仓 **2692通过、88项按环境跳过、0失败**。Linux结果补齐这些环境限定项。
- Linux golden：**87/87逐字节一致**，未修改基线。
- Black、isort、mypy、生成调用合同和场景清单检查全部通过。
- 合并源码独立构建wheel，在仓库外加载；固定工位、家居显式选法、自动选法、禁止搬位、玄空有限解释共5类请求的REST／FastMCP／CLI结果一致，非法引用三端均拒绝。新增规则JSON已打包。

候选位置的玄空用途独立重算；历史宅运、当前评价运、年盘、室内形态及外局存在事实保持分层。有限解释层覆盖81对有序五行关系，不等于81对专门断语；完整外局质量、自动户型规划及未实现流派继续明确标为未覆盖。

冻结副本及工作区源码在验收结束时均无漂移；冻结后仅更新本报告、验收JSON及玄空解释文档的合并验收说明。原有153项工作区变动中148项原样保留，5项共享合同／技能文件在原内容上扩展；暂存区与HEAD未变。临时Linux环境已恢复停止状态。未运行托管CI、新Desktop真实模型咨询或现场效力验收，未提交、推送。
