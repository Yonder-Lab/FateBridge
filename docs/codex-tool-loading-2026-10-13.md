本轮保持桌面原生 `0.162.0-alpha.17.2`、`gpt-6.1-sol`、high 推理强度、保存的插件配置与全部 87 项 FateBridge 工具。用户消息没有工具名称，临时对话正常加载仓库 AGENTS，没有脚本角色或强度覆盖。优化前重新观察 3 轮，优化后共完成 18 轮真实对话，其中 5 轮没有启用新增观测开关。不是对现有 GUI 窗口的直接计时，也没有替换模型或缩减计算结果。

## 根因证据

上一轮只看到一次业务 MCP 和四次用量更新，无法辨认隐藏往返。本轮为临时诊断线程启用原生 `experimentalRawEvents`，记录 `rawResponseItem/completed` 与 `rawResponse/completed` 的安全元数据。

两组修复前事业咨询均有三次 `exec` 调用和四次上游响应。第二组具体出现：

1. `ALL_TOOLS.filter` 展开候选工具。
2. 又一次 `ALL_TOOLS.filter` 筛选工具定义。
3. `tools.mcp__fatebridge__bazi_career` 执行实际计算。
4. 上游生成最终解读。

因此，之前“没有读取 MCP 发现资源”不等于“没有工具发现”。这里多余的是代码模式的第二次筛选。筛选操作本身很快，但输出返回后模型需要再次处理上下文、计划并发起下一次调用。优化目标是减少串行模型往返，而不是微调约 0.1 秒的 Python 计算。

公开事件仍不能独立拆出远端排队、预填充、模型内部处理与网络传输。不能把两个响应之间的时间全部归为推理，也不能把事件数和上游费用画等号。

## 已修复

- 仓库根目录 AGENTS 明确常见问题的主证用途。代码模式一次返回所需工具的完整条目，包含参数定义；不先展开全部候选再检索同一工具，不只返回名称。用途确有歧义时仍可比较候选。
- MCP 连接指令采用同样的规则，让已连接客户端获得一致指引。参数 Schema、输出 Schema、计算规则、首轮字段及精度说明没有删减。
- 资料缺失或日期明显无效时先追问，不提前发现工具、加载契约或排盘。一次无效日期对照出现两次响应，未启用原生观测，无法追溯具体用途；另一组在新增防护前已只用一次响应，所以不能将全部改善归因于该句指令。
- 新增可选 `--trace-tool-loading`。消息、推理、加密内容和工具输出正文在进入观测队列前移除，只保留类型、工具标识、代码调用标识、字节数及时间。日常接入不需要开启这个诊断选项。

## 真实日常对话验收

优化后的 18 轮全部完成，没有连接错误、后台记忆/目录命令或业务工具报错。需要计算时均只使用一项主证；有原生观测的轮次均只加载一次定义，随后一次计算、一次解读。正常对照的响应次数一致，但未观测的隐藏调用不反推具体用途。

- 事业与辞职追问：保留实际事业类型、创业倾向、阶段/年度时机；区分全年信号与即时辞职窗口，后续解释不重新计算。
- 缺时刻、补齐、又不确定：先追问；补齐后计算一次；撤回精确时间后不沿用确定盘。
- 双人相处与分数追问：使用 `general`；说明 54.5 加权分、8 净分、39 摩擦维度的不同口径，不平均、不当成功概率。

- 布局缺资料：同时询问户型与方向，不猜朝向、不计算。
