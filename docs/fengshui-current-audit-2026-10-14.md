# 风水布局对象的使用人作用域修复

本次修改基于 `1da5e4f`，解决一个对象无法关联部分住户的输入合同缺口，不新增传统规则或几何布局算法。

## 问题与结果

住宅的住户集合不等于每件家具的使用人集合。原合同只支持 `subject_id` 单人或省略后应用全部住户，无法表达甲乙共用床、丙独用书桌；同时提供丙的资料会错误改变共用床的个人共同方向。

新增 `Placement.subject_ids` 表达实际使用人集合。八宅正向判断和布局反向候选复用 `applies_to_occupant`，元素目标及跨作用域关系继承相同筛选；未使用该对象的住户不会参与它的判断。住宅宅盘独立保留。

- `subject_id` 与 `subject_ids` 的非空选择互斥。
- 多人集合非空、唯一且最多50人，必须引用本请求已提供住户。
- Schema 和运行时同步校验，显式 null 与省略兼容。
- 单人列表与原单人字段、全集列表与原省略字段保持完整业务输出一致。

[前后复现证据](audits/2026-10-14/fengshui-product-user-membership-reassessment.json)使用合成资料和独立基线源码计算。新增39项业务测试覆盖四用途、七个使用人集合、八方向，以及集合校验、兼容行为、元素目标和 REST/MCP/CLI 一致性；期待值采用实际使用人的独立请求，未硬编码单个案例的方向答案。

## 接口与咨询边界

工具描述、MCP 指引、两份 AGENTS 和指南同步使用人语义，同住不能自动推成共用；更正使用人应替换集合后重算。观察和行动约束分别保存，预算或禁止新增不能证明当前物理条件，未知布尔观察保持省略。

匹配方向只表示所选规则候选，不证明现实可搬动或健康、财富效果。没有提供使用人字段时仍应用全部已提供住户，这是旧合同的兼容行为，调用方须明确对象的实际使用者。
