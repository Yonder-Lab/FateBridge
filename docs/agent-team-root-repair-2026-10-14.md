## 计算、覆盖、行动分别表达

保留旧 `status`，新增以下位置的 `analysis_progress`：

- `coverage.analysis_progress`：首轮与 coverage-only 读取可得到整体进展。
- `layout_analysis.analysis_progress`：布局摘要。
- `layout_analysis.surface_analysis.analysis_progress`：桌面局部摘要。

| 字段 | 作用 |
| --- | --- |
| `calculation_status` | 所选计算所需事实是否齐备，complete/partial |
| `rule_coverage_status` | reviewed、needs_confirmation 或 limited |
| `assessment_complete` | 当前事实的审查是否完成，与是否需要／能够行动分开 |
| `rule_coverage_counts` | 已支持、已确认无规则、未知属性／观察；另注明计数单位，不当作规则数量 |
| `action_readiness` | ready、needs_confirmation、blocked、mixed、no_action_needed 或 not_evaluated |
| `action_counts` / `optional_action_count` | 各类候选数量及其中可选方案数量 |
| `pending_confirmations` | 事实／对象／动作、原因与用途：assessment、action 或 optional_action |

每个桌面动作具有稳定 `action_id`、`optional` 与确认清单。方向、形态、元素和年度候选也保留作用域与可行性限制；年度确认指向 `annual_remedies.findings`，不会错误关联元素分支。

新的行为包括：

- 计算与规则审查可以已完成，而植物移动仍待确认目标区空间。
- 已确认普通手机无独立规则，可以结束该对象的审查；未知物件不会冒充“确定无规则”。
- 禁止移动或不可用区的动作没有执行条件追问；仍未确认的物件属性可以保留独立审查缺项。
- 可选新增候选不成为必须购买、摆放或补资料的任务。
- 无足够事实生成行动时为 not_evaluated；已知作者版本不支持某年时显示 limited，不宣称现场无需调整。
- 更正入口视野后，对应镜面候选和待确认事项消失。

已同步公共嵌套 Schema、首轮字段、生成调用合同、风水 Skill、咨询参考及相关 API／架构文档。当前 ready 仍只覆盖现有合同的属性、许可及区域门槛，规则中的现场复核条件继续有效。

## 分页性能与数据完整性

主代理使用修复前备份和当前实现，对相同虚构载荷做本地对照：一次预热、三次记录，取中位数。计时只包含完整 `store.page` 读取，不含写入、IPC、网络、宿主或模型。

| 载荷 | 页数 | 修复前 | 修复后 |
| --- | ---: | ---: | ---: |
| 200011 字符，约 360 KB | 98 | 99.36 ms | 13.29 ms |
| 800011 字符，约 1.44 MB | 391 | 1704.19 ms | 51.74 ms |

四倍载荷的修复后读取约四倍耗时。测试通过实际读取字节和禁止逐页全量解码／序列化／散列来约束复杂度，不用易波动的计时阈值。每次对照均核对原值与全文散列。独立审查另以 40 份随机嵌套文档核对 2640 次字段路径／offset／散列，全部通过。上述本地改善不等于 Desktop 对话整体等待已改善。

原 `.json` 的 `payload` 与 `file_path` 消费方式继续可用。旧记录保留原 ID、回执及过期时间，首次读取按规范格式升级。64 MiB 约束已提交存储；旧记录升级的原子暂存替换文件可能提高瞬时磁盘峰值。
