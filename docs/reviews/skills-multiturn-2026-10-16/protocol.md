# 自然多轮验收方法

本次以虚构用户情境执行真实模型对话和已连接 FateBridge MCP 调用。用户消息由独立案例设计代理预先编写，逐轮发送；咨询代理每次只收到当轮消息，自己读取项目技能、判断缺项、选择计算、解释返回结果。没有向咨询代理提供预期工具、检查点、正确结论、未来消息或旧审查报告。后续通过同一代理的新 turn 延续上下文。

- 基线：9个独立上下文，每项技能一个主要使用路径，各4轮，共36轮。技能树在36轮全部结束时与起始快照逐字节一致。
- 第一轮修订复测：画像、时运、关系各用新的上下文重放4轮；另以不同出生资料、性别、地点和问法做2轮画像留出检查。使用 `revised/skills`。
- 第二轮修订：首次复测的时运仍先取流年详情、再补聚合。进一步澄清工作流后，使用 `revised-2/skills` 和另一位虚构人物做2轮时运留出检查。
- 第三轮修订：最后一组仍有“相对本命增强”与“跨年增加”的参照歧义，以及内部日期锚点未明示的问题。补充规则后，以同一案例的自然澄清再问1轮，重新读取 `revised-3` 技能并复用已有结果。这是明确记录的追加追问，不当作前两轮原本没有问题，也不当作独立新上下文试验。
- 审查：另一个代理逐项核对输入、原始返回、答复、数据作用域和具体可用性。允许多种合理计算路径；没有固定某个分数、卦象、生活选择或逐字回答作为标准。

人物和问题见 [cases.json](cases.json)、[retest-cases.json](retest-cases.json)。预先制定的检查点见 [private-checks.json](private-checks.json)；该文件仅供审查。最初设计中的事业目标年在正式发送前改为2026年10月，检查点也按实际公开消息校正；所有实际发送的文字保留在案例文件中。

## 原始证据

`logging-helper.txt` 调用实际的 `tools.mcp__fatebridge__*`，随后保存原始参数、response、异常、时间、散列及可访问的延后结果文件。没有用模型生成或手写的计算结果代替工具返回。编号JSON和 `.bin` 在归档时按字节复制；原始metadata中的临时绝对路径保持不变，搬迁对应关系见 [archive-path-map.json](archive-path-map.json)。

这些记录便于复核本次观察，不是独立的服务签名或真实性证明。记录器的合成自测数据未收入本报告的真实调用统计或归档。哈希只核对文件一致性，不证明预测效力。

普通 `exec_command` 读取临时结果的命令在早期案例没有统一记录。b有事后消费说明，c另有当时保存的读取记录；两者证据性质不同，不能把事后自述当作原自动日志，也不能把审查快照自动视为模型已读。后续复测增加 `result-reads.json`，技能读取路径登记也不等于对全部引用文件的读取过程均已归档。独立审查保留这些边界。

b第4轮未保存单独的 `user.md`；其实际消息已在 `cases.json`，派生对话页明确注明来源，没有补造当时的文件。原始答复和错误未改写。

## 运行环境与结论范围

原计划的独立 Codex CLI 预检，在模型输出前因当前配置的模型不被该登录方式支持而失败；同时出现全局技能目录超预算提示。未更改全局模型、技能或MCP配置。随后使用独立协作代理和真实已连接MCP执行逐轮测试，见 [cli-preflight.json](cli-preflight.json)。这是模型代理加MCP的咨询验收，不是独立CLI成功验收、人工Codex Desktop界面验收或真人满意度测量。

当前连接可能缓存旧工具描述；本轮没有重启用户的活动连接。新首轮建议字段通过本地新建MCP、CLI及实际公开的REST路径验证。`analyze_destiny`本身没有REST路径，测试没有为它恢复已退役入口。

覆盖九项技能的主要路径不等于穷尽所有流派、关系类别、异常环境和工具不可用分支。每种问法和每个版本的样本数很少，不能据此宣称准确率、满意度或普遍质量提升。命理、占星与卦象的现实预测效力不在本次验收结论内。

归档和对话视图可运行 `build_artifacts.py` 从本次临时目录重建；它只复制已保存的观察，不重新计算，也不模拟新的模型回答。重新做对话验收应使用新的输出目录和新上下文，按案例逐轮发送并保留失败。
