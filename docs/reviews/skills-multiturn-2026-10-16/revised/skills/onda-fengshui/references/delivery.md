# 结果交付与方案对照

本参考用于把实际结果变成用户能核对的空间判断，不新增风水规则。单项问题先答要点；逐对象、完整审查或多方案请求才展开相应表格。不同请求不必套同一份整宅报告。

## 从用户的问题组织结果

先说本次已经有依据的结论和最相关的理由，再说明它适用于什么对象、关系或方法。工具状态留在取证层，用日常语言解释给用户：

| 实际返回的依据 | 可以交付的含义 |
| --- | --- |
| 已确认观察符合所选规则 | 说明这一点为何可保留；结论只限本次判据，不扩大成整张桌、整屋或全家均有利 |
| 明确关系不成立 | 说明这条顾虑本轮未触发；不从单条未触发推出整体吉凶 |
| 已确认观察触发作者提醒 | 点明哪两件对象、哪种关系及该作者的理由，再给条件式方向；有作者异议时并列说明 |
| 只有照片或未知事实 | 先按照片所见作条件式解释，指出哪一事实若改变会使结论不同；只追问影响当前问题的项 |
| 明确没有独立规则 | 直接说明没有依据要求这件物品搬到某个吉侧；可由实际使用需要安排，不继续追资料求出吉位 |
| 只有原始星数、象意或参考表 | 说明算出的内容与适用范围；未实现的综合判断单列，不把星数／职业类比写成摆放处方 |

无规则与资料未知分开。`scope_only` 可以结束能力范围说明；`conditional` 可以交付条件判断；行动尚未 ready 均不抹掉已知依据。

## 逐对象让依据可见

使用本次请求中的名称及稳定对象对应，避免镜、桌、房间或使用人混淆。完整审查可用下表；每个被点名对象都应有结果，允许写“未覆盖”。两端关系放同一行，避免拆成两个互不相干的物品吉凶。

| 对象／关系 | 现场依据 | 本次判断与理由 | 调整与条件 |
| --- | --- | --- | --- |
| 使用本次对象名或两端关系 | 用户确认／实际测量／照片候选的原粒度事实 | 对应实际 finding、规则及作用范围；保留作者异议 | 已有依据支持保留、条件方向、具体可行动作或未覆盖 |

这是格式说明，不是可复制给用户的示例结果。没有实际返回的判断不能填入；不要求每行都有动作。简单问题用一两句连起同样的事实与理由即可。

取证时按实际请求读取已有分支：

| 用户关心什么 | 已有字段如何支撑 |
| --- | --- |
| 门床桌灶的位置／朝向及使用人 | `layout_analysis.placement_findings`，按方法、对象、使用人及 location／facing 区分；个人关系需要时用 `layers.bazhai.occupants` |
| 入口、背靠、直冲等形态 | `layout_analysis.form_analysis.findings[].checks`，逐条翻译实际 finding 与 adjustment，不从入口方位推直冲 |
| 镜照床、厨卫、梁管和尖角两端 | 实际提交关系时读取 `layout_analysis.interior_analysis`，保留 predicate、exceptions、分歧和 action_basis |
| 材质器形及代表物资格 | 实际提交属性时读取 `layout_analysis.material_analysis`，只解释独立属性和用途资格 |
| 用户明确另选 BTB 的桌面物件 | `layout_analysis.surface_analysis.findings` 的 item_findings 与 action_options，按物件覆盖和动作状态分别说明 |
| 方向／宅盘尚未齐 | `method_policy` 与 `coverage.scene_scope` 说明实际计算层及未选原因；已完成形态仍照常解释 |

字段是内部取证路径，用户不必理解字段名；可缺分支不能无条件加入严格投影。解释已有结果时复用同一 run；若结果在 `result_delivery` 中，按共享交付合同读同一份结果，不重新计算。

## 有候选时让差异可见

比较现状与用户实际给出的候选；只有方向列表时先解释方向取舍，不伪造能放家具的位置。候选新事实的独立核对遵循[咨询闭环](consultation.md#交付与复核)。

以本次关心的判据为行，以现状和候选为列。仅纳入实际算到的层和用户关心的限制，候选数多时分组；对每个差异说清改变了哪一关系及其理由。

| 比较项 | 现状 | 候选 A | 候选 B（如有） |
| --- | --- | --- | --- |
| 已有规则下的具体关系 | 现状真实结果 | 新位置独立结果；没有新证据则待确认 | 同左 |
| 人宅、形态或两端关系的权衡 | 依所选层说明 | 实际改变或保留的判据 | 同左 |
| 许可、容纳与通行 | 已知限制 | 本候选执行条件 | 同左 |

比较以 `alternatives_analysis.findings[].rule_comparisons` 为依据，同时读取各项 `comparison_scope`、`layer_statuses`、`missing_inputs` 与 `pending_confirmations`；现状取对应原始结果。年星／历史宅盘比较限返回的星数、角色与落宫参考；材料资格不升级成摆位判定。若两种作者结论不同，保留各自条件，不平均总分，不把 ready 当综合赢家。

用一句话帮助用户理解取舍：某候选改变了哪条已知关系，仍保留什么限制，是否值得为了本次目标进一步确认。只有依据足够时才表达偏好，并注明这是对本次判据及现实约束的取舍。候选均受限时，可交付保留现状的理由与局限，不强找摆件或新增采购。

## 收尾与后续核对

集中注明实际采用的方法／作者版本和来源标题或链接；每条主结论能回查到返回的 `rule_trace` 与 `rulesets.sources`。软件检验、作者规则和用户现场观察分别说明，来源可追溯不等于现实效力已验证。

把剩余项目说到当前问题所需即可：会改变判断的事实只择一至两项追问；仅影响动作落实的条件随该动作说明；没有规则的项目明确结束范围说明。不把全部 missing_inputs、未选方法或研究原型列成必补资料。

调整后用可观察的结果复核，例如实际入口是否仍可见、镜床关系是否仍成立、通道是否畅通。用户更正事实才重建受影响输入并保留 trace／父 run；解释未改变的结果不重算。不把传统标签或软件运行成功当成事业、财富、健康已经改善。
