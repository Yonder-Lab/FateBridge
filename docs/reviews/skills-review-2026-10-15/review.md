# FateBridge Skills 深度审查与改进

日期：2026-10-15，Asia/Shanghai。范围：全部 9 个项目内场景技能、共享参考、发现元数据、默认首轮取数及实际咨询交付。团队分三组审查和修改，再由独立代理复核语义、生成新旧答复和盲评。

## 结论与可直接查看的结果

主要问题是计算结果到用户问题之间的解释不够明确，同时存在会拿错人物、阻断调用或宣传不存在取法的实质错误。继续增加调用数量不能解决这些问题。

本轮已更新全部 9 项技能及其展示／接口配置，增加按问题交付的参考，修复首轮依据不足和跨文件路由冲突。计算公式未改；公共工具目录改的是取法与能力描述，避免技能与真实工具说明互相打架。

- [九场景交互对照页](showcase.html)：同一批保留结果的 18 份原始解释，可切换场景及显示基线。
- [评阅任务与检查点](cases.json)、[独立语义审查](independent-audit.md)、[盲评](blind-comparison.md)。
- [实际计算及散列清单](evidence/manifest.json)、[技能快照散列](skill-snapshots.json)、[九项技能格式校验](skill-validation.json)。

旧技能已有不少正确边界，也能给出好回答；本轮没有证据支持“以前全都无效”或“新版全面胜出”。本轮更明确的进步是把能力和交付写具体，并修复可复核的合同与语义错误。样例质量与后续真实使用效果分别评估。

## 发现并修复的实质问题

| 问题 | 当前实现核对 | 本轮处理 |
| --- | --- | --- |
| 星盘、紫微、梅花首轮取数过窄 | 标准盘只取角度、盘型和太阳一句话；紫微只取命身宫位置；梅花缺动爻、体用和问时 | 标准盘补星体与相位、情绪描述；紫微补宫位星曜和四化；梅花补问时、动爻、体用与提示。实际严格投影通过 |
| 孩子本人与父母的子女宫混用 | `analysis/children.py` 按命主性别和四柱解释其子女星／宫，不是儿童性格算法 | 分开孩子本人性格／学习与命主子女缘；前者使用孩子资料，后者使用命主资料 |
| 核心星盘错误要求用户查坐标 | `AstroChartRequest` 可由已支持的出生城市解析坐标；西占默认民用钟 | 核心盘不再无条件阻断；关系／推运仍按其实际必填坐标核对，中西太阳时策略分别保留 |

| 星骰／梅花被误写成随机取法 | `otherbu` 归一化传入骰面；梅花按年月日时取数 | 明确已有骰面解释与按问时取数，不假称随机抽取，不暗示塔罗牌阵 |
| 普通关系决定自动转占卜 | “要不要复合／表白”及机读触发词与“明确求卦才起卦”冲突 | 仅明确求卦／选定术数时进入问事，前提写入机读路由条件 |
| 机读路由丢失择一条件 | 生成器只读取表格单元格，段后“八字或紫微择一”说明不会进入发现接口 | 条件写进单元格；孩子性格／学习拆行；中式默认／西占视角分开，重新生成 manifest |
| 单一体系结果被自动降级 | 共享层称“只有一套提到就是弱信号”，与画像技能保留来源的要求冲突 | 改为说明来源和范围；另两套未提及不自动表示较弱，多体系一致也不是独立统计证明 |

另修正：`fields` 请求投影目前不能用 `planets.0` 这类数组索引；结果交付资源支持数字索引不代表初次投影也支持。最终首轮使用完整 `planets/aspects/palaces` 字段，读取后按实际名称挑选相关项。

## 验证与观察边界

1. **工程验证：192 项通过。** 技能／接口合同、全部可执行文档示例、场景覆盖、实际咨询入口、新投影三端一致、调用合同、西占钟时与占卜回归。保留现有依赖的 5 项警告，没有把它们当成领域预测验证。
2. **9／9 技能格式校验通过。** native UI 描述长度、技能名引用、本地链接及生成清单另行核对；lint、格式和 `git diff --check` 通过。
3. **11 个工具真实独立 stdio MCP 计算。** 固定虚构资料与 `as_of`，保存 input、完整 result、run／trace 和业务散列。三项新首轮另行调用验证严格投影与预算，业务散列与完整结果一致。已保存样例总字符为星盘 6365、紫微 7339、梅花 4165；其他输入更大时仍可正常使用同 run 交付资源。
4. **9 场景 × 2 份解释。** 两个新上下文分别读取基线／领域修订快照；双方使用同一结果，不重新计算。保留原始回答与 trace，再由另一新上下文盲评。详细结果见[盲评文件](blind-comparison.md)。
   解盲后为 **7 项持平、全面画像修订版有有限优势、学习案例基线略优**。两边均未发现实质事实错误；85 个证据路径得到核对。学习案例中，基线把同一门课的两种方法和隔周反馈连接得更清楚；修订版也正确，但没有证据证明更好。保留原始答复，不为制造提升率改写结果，也不据单次偏好过拟合技能。[解盲映射](blind-mapping.json)已保存。
5. **定性对照限制。** 每版本每场景一次，且同一代理顺序处理九项；提示词较具体，可能使两版本都表现良好。基线六份风水引用因并行迁移从 Git HEAD 补齐，不能声称所有参考文件严格控制变量。修订解释快照冻结后，独立复审又修了若干路由／取法文案，见上文；18 份解释不是最终入口行为的完整验收。

## 改动范围及仍需后续验证的事项

本轮修改项目内 9 项技能、两份原有共享参考及新增交付参考、技能 README、场景路由与生成清单、三项 suggested_fields、五项占卜工具的说明、三端证据回归测试和本目录产物；生成区用脚本刷新。没有修改计算公式，没有改全局 skills，没有 commit／push。

工作区原有风水工程仍有其他活动持续修改，并迁移了部分规则资料到技能 references。它们不计为本轮新增计算能力；同文件上的既有及并发改动保留，未替其他任务签工程验收。代码和入口快照都有时间范围，未将其中的研究／新接入分支推广为当前连接已支持能力。

健康引擎仍输出传统病名等标签，本轮修的是咨询层和入口承诺，不是医学能力；若要进一步减少数据层误用，应另做服务措辞与合同审查。自然问法、多轮更正、工具缺失、延迟和用户满意度仍适合后续真实会话检验；本轮未用单次样例推算提升率或满意度。

三组详细取证记录：[生活场景五项](audit-notes/life-review.md)、[星盘／画像／问事](audit-notes/chart-review.md)、[风水](audit-notes/space-review.md)。这些保留各组当时发现的状态；合并后的处理以本报告和最终代码为准。

最终收口另核对了公开发现接口中的求卦条件、三项分支的输入范围，以及五项真实 ToolSpec 文案，记录见 [final-semantic-checks.json](final-semantic-checks.json)。独立审查报告中等待根代理核对的上述问题已按本轮最终状态处理。
