# 工位与家居选法、约束及候选布局

这是一套通用的场景选法与可行性合同。主要方法为九宫飞星、金锁玉关、八宅；[2026-10-15 用户专家访谈政策](fengshui-expert-policy.md)增加明确的核对次序和环境上下文，不添加合成分或流派权重。传统关系仍来自原有版本：立春年星、中州派玄空、有限金锁砂水、八宅坐山法及署名室内形态；现代桌面 BTB 只在用户明确另选时保留作者辅助。软件验证只能确认合同和计算，不能证明运势效力。

## 选法与兼容

`fengshui_assess` 可显式传 `scene=workstation|shared_rental|home`。用户明确的 `methods` 始终优先，包括独立形态的空列表及显式另选桌面作者法的请求。

公开Schema用 `methods=null` 表示自动选法。MCP会物化参数默认值，因此不能发布旧三法列表为默认、再试图区分字段是否省略；null与省略在三个传输中采用相同路径，内部归一为实际方法列表。`coverage.scene_scope.selection_policy`说明选法策略，不把传输归一化后的字段错误标记为用户原始选择。

未传方法且有场景时，只按已提交事实选层并依次检查：提供玄空请求选择历史宅盘、明确年度选择年星、确认环境特征选择金锁、位置及宅／人资料选择八宅（home 也允许先排宅／人盘）。工位／合租优先飞星家族，其次金锁，再按问题加入独立八宅命卦；年星与历史宅盘仍是两层，互不补缺。`method_policy` 交付核对优先次序与实际已选层，`method_details` 交付带来源细节。场景本身不生成任何观察、方向、生辰、年份或宅运。没有足够资料时保留缺失。

首轮看 `method_policy.priority_review_status` 及每法 `not_selected_reason`，区分自动缺输入与用户显式排除。实际已选层 complete 不表示优先方法全部覆盖；明确排除的方法不继续追资料，需要的未选层只按当前问题核对必要事实。

未传场景且未传方法的独立形态/桌面请求同样按事实选层，不再强制补充三法资料。其余无场景旧请求保留原先八宅/金锁/年星默认，原始计算与 golden 基线保持兼容。

所有场景均先核对事实质量与允许动作；工位／合租在方向可用时按飞星、金锁次序分析，方向不足时先完成已支持的视野、入口直线、背靠等形态审查并保留方向层待确认。家居同时关注住宅范围和对象落宫。`coverage.scene_scope` 说明结果只覆盖已提交对象与所选规则。八宅个人命卦不等于完整住宅判断，坐山八宅不等于独立《阳宅三要》结构法，年盘不等于历史宅盘，桌面近远左右不等于罗盘。个人八字／紫微喜忌及相关人喜忌不得补入环境输入。

`environmental_context` 另存方位／户型对齐／立极确认、家庭与生肖、各楼层／一层院落、明确厨卫／材质／器形事实。该层的家庭主宫、生肖索引和次级对宫不修改八宅住户集合；角色范围与对象实际使用人仍分别确认。多层同方向不表示每层同边界或同形态，局部不利是否外推按已确认的影响范围及异层适宜性处理；共享门路外局继续复核。拱门／开放厨房低优先适度提醒，不仅因样式推拆改。参数与未覆盖项见[专家政策](fengshui-expert-policy.md)。

各层及独立院落分别确认 `floorplan_alignment_confirmed`、`center_confirmed`，并以 `uses_shared_orientation=true` 显式采用已确认全宅方向；全宅方向／中心不替代逐层确认。缺门槛时，不传关联该层对象的实际落宫。逐层位置只关联本次已声明的宅盘／年盘，不自动建立楼层宅运或自动立极；候选上下文也独立核对这些状态。

使用人名单是另一条独立证据：`floors[].subject_ids` 仅表示已确认使用者，未列者仍可能使用，默认空列表也不是无人。需要排除某人的本层／共享局部影响时，对有关空间核对完整使用范围，成对提供 `usage_confirmed=true`、`usage_evidence`；未确认不得豁免。正向使用已经成立或不做负向排除时不额外追完整名单。家庭象意解释可用 `household_scope=symbolic_reference` 而不追罗盘，但不能免去同时请求楼层分析的物理条件。

完整楼层名单与其中对象显式 `placement.subject_id/subject_ids` 一致：已知对象使用者不得被该层完整名单排除。对象省略 selector 仍保留既有计算兼容语义，不因此推断真实使用人。

## 家具动作约束

`layout_constraints` 每个对象一项，引用已有 `placements`、`form_observations` 或 `environmental_context.objects` 中的实际对象。镜面、尖角源等可有自己的许可；不能将床／桌的许可套给另一端，也不因对象已登记就允许改动梁、墙、门或管线。

| 字段 | 含义 |
| --- | --- |
| `object_id` | 已有家具对象 |
| `can_relocate` | 是否允许搬位；包括同一宫内换位置 |
| `can_rotate` | 是否允许转向 |
| `can_add_items` | 是否允许新增相关物件 |
| `evidence` | 用户约束依据；不能为空白 |

三种许可接受布尔或省略，未知不当作允许，也不当作禁止。方向关系的反推候选不因“允许搬动”成为 ready。形态行动按对应动作筛选：直走道、入口直线和梁下位置需要搬位；入口视野可涉及搬位或转向；背靠也可能涉及新增支撑。没有确认的外部物件调整不能由对使用者家具的禁止反推为可做。镜面新增、元素新增单独受新增许可约束。被禁止的行动标记 blocked，动作待确认清空，现状观察的缺失仍保留。

旧尖角座位观察没有源物件 ID，动作只分目标座位搬位和新增叶状屏障，各自检查搬位／新增许可；不能生成搬转未知尖角源的动作。新 `interior_relations` 按已登记源／目标和具体规则逐动作核对许可，只交付 `conditional_option` 或 `blocked`，不在关系模块直接返回 ready。主门正对厕门没有已登记非结构动作，不能为它自动编屏风或拆改。

桌面小物移动继续使用 `surface_constraints`，不把 `can_move_items` 混同家具搬位。同一书桌的新增许可不得互相矛盾；家具层明确禁止新增时，桌面可选新增也会被阻止。

## 独立候选

`layout_alternatives` 每项包括：

- 唯一 `candidate_id`、已有 `object_id`、`evidence`。
- `changes`：`location`、`facing` 中的一项或两项；同一宫内的移动也要声明。
- `placement` 和/或 `form_observation`：涉及位置／形态计算时提交新方案的独立事实，对象 ID、用途及原有使用人集合须一致。镜面、尖角源等双对象关系方案也可只提供 `environmental_context`，但其中须至少有一条关联候选对象的 `interior_relations`；不为凑候选伪造床／桌／灶位置。
- `environmental_context`：候选独立环境上下文，不继承顶层现状的家庭、楼层与观察。现状对象涉及楼层／环境观察时，新方案须逐维度重核，不能用空对象绕过缺失；位置变更后的适宜性和影响范围另附依据。
- `features`：该候选对象在新位置独立确认的金锁砂水特征；只可引用同一 `candidate.object_id`，方向须与新 `placement.location_direction` 一致，且分类依据／证据齐备。其他固定特征继续保留，不借此修改其他对象。
- `physically_feasible`：逐方案确认容纳家具、通行和操作空间。与动作许可分开；未确认则省略。

候选使用原来的八宅、金锁、年盘、玄空和署名形态规则重新计算。每个方案独立，不继承移动/转向之前的入口、背靠、窗、横梁或尖角关系。现状曾采用的位置/形态证据在候选中缺失时，候选保持待确认，不能只挑有利层计算。当前事实审查完成与可选候选待确认分别记录。

候选对象出现在旧 `interior_relations` 任一端时，新上下文必须独立确认同一 `kind` 与原源／目标的关系；另一端固定也不沿用。确认 false 仅解决该关系，null、照片或省略仍待确认，不能换类型绕过旧项。原 `material_facts` 也按材质、器形、颜色、活植物状态及明确代表物问题逐项重核，不把一个属性换成另一个属性。具体范围见[有来源的室内规则](fengshui-sourced-interior-rules.md)。

固定关系端已有楼层即使省略仍保留用于校验。候选目标改换楼层／空间作用域必须声明 `changes` 包含 `location` 并核对搬位许可，不能仅声明转向。已确认属性及 `plant_alive` 布尔不能随搬转改写；照片／未知可以确认，实际事实更正则先替换现状。

现状家具本身也是金锁 `feature` 时，候选用自己独立确认的 `features` 取代该对象原来的方位／分类观察；不能同时保留同一对象搬动前的砂水结果。旧对象已有特征而候选没有新特征时，即使允许搬动且 `physically_feasible=true`，仍保留待确认，不能输出 ready。候选返回 `environment_adjustments`，`rule_comparisons` 包含金锁比较；其他未移动的固定特征可按原事实继续计算。

非目标固定特征不能被候选上下文换到另一楼层／坐标；未重列的固定特征在结果中继续保留原楼层元数据。`rule_comparisons` 也列已算年星／历史宅盘的星数、角色及落宫参考，并以 `comparison_scope` 限定其非组合吉凶。候选 `layer_statuses` 提供各层真实计算状态，方法策略分别记录现状和候选可用性，不以现状 complete 代替候选已审。

候选另有自己的 `interior_analysis` / `material_analysis`，并在 `rule_comparisons` 标明仅为独立关系判据／来源限定的代表物资格比较。关系成立、材料资格或参考主题都不认证摆位有利，也不替代许可与 `physically_feasible`。

有现状上下文时，旧对象关联的楼层和环境观察也是候选必须重核的维度；即使许可及空间已经确认，缺失仍为 `candidate_only`。候选输出自己的 `environmental_context` 并标记 `old_environmental_context_reused=false`；只提供空上下文、旧楼层身份或新位置好看的照片，不证明新楼层适宜、局部影响范围或厨卫关系仍成立。

结果位于 `layout_analysis.alternatives_analysis`，投影时显式追加该分支：

- `ready`：所选计算与动作门槛满足，仍需查看每条规则是否匹配。
- `conditional_option`：计算完成，许可或实际可行性待确认。
- `candidate_only`：候选观察/计算不足或只有照片。
- `blocked`：必要动作被禁止或明确无法容纳，无动作追问。

`rule_comparisons` 保留方法、宅/人、候选性别约定、位置/朝向及形态规则。`ready_candidate_ids` 不是推荐名单；不存在综合分数、固定流派权重或自动赢家。年盘和玄空只关联落宫关系，没有完整星组合或外局依据时不作 relocation 排名。

## 明确未覆盖

当前缺乏的完整方法在工具结果中保留，不能用“算法已成功”覆盖：

- 自动识别户型、自动立极、任意不规则空间分宫、整栋/单元/房间自动对齐。
- 完整古典内外形势、砂水形态与现场激活条件。
- 未登记的厨卫／镜面／器形泛化规则；当前仅覆盖明确列出的 12 条作者关系与有限材料资格，不将材质或器形本身判为普遍禁忌。
- 独立《阳宅三要》门主灶结构版本、三合水法、玄空大卦。
- 完整玄空星组合、旺衰用途与外局判定；目前宅盘提供运/山/向星、落宫和有条件元素关系。
- 实际效果大小、事业财富健康预测。

这些项目需要各自经过来源、版本、输入及反例核验后实现，不能把现有八宅异或表重新命名为另一流派，也不能从几个作者案例归纳通用规则。

## 调研依据

- [2023 年系统综述](https://www.sciencedirect.com/science/article/pii/S2405844023067403)：纳入36篇实证研究，结果质量与因果证据受限；不支持将流派规则一致性视作运势效果。
- [2026 年泉州建筑微气候研究](https://www.nature.com/articles/s40494-025-02289-3)：特定建筑与夏季条件下的朝向/通风关联，不能外推为普遍个人吉向。
- [Joey Yap：House Gua、Life Gua 与位置/方向](https://joeyyap.com/tutorial/tutorial-details.asp?tid=333)。
- [Tori McBrien：Command Position](https://www.ifsguild.org/the-feng-shui-command-position/)：明确作者及 Black Sect 范围；不扩大为所有古典形势。
- [2005 年住宅功能与风水约束系统](https://www.tandfonline.com/doi/pdf/10.3130/jaabe.4.347)：提供约束建模先例，不证明传统效果。

选法和动作筛选是本项目明示的工程策略 `layout_feasibility_v1`，不是新增传统规则集；既有规则的版本与原始来源继续由 `rulesets` / `rule_trace` 返回。
