# FateBridge + Codex 风水布局产品审查

日期：2026-10-14。资料均为合成体验资料，没有使用历史人物资料。本报告针对 FateBridge 通用风水咨询，不把方向规则计算当成实际运势效果验证。

## 产品判断

产品成功应当是：用户知道在自己已确认的布局和现实约束下，哪些调整有选定规则依据、哪些需要补信息、哪些可以保留；调整后或纠正描述后，旧判断能被撤回并正确重算。`complete`、工具调用成功、出现免责声明、给出更多建议，都不能单独证明这一点。

当前核心已有可靠的规则边界：位置与朝向独立，宅与人分开，年度规则不外推，未知形态不补成布尔值，作者分歧保留。影响用户效果的主要缺口是这些正确计算怎样经过模型成为正确且可实施的行动，而不是再给家具添加未经核对的吉凶规则。

## 从第一性原理追踪任务链

| 必须完成的步骤 | 当前问题与证据 | 通用修复及验收 |
| --- | --- | --- |
| 用户描述变成可信事实 | 模型在形态首轮发现资源、读取嵌套契约后仍创建没有位置/朝向的 `placements` 占位，调用失败后自行恢复；代码模式定义将引用数组项呈现为 unknown，增加另行发现成本；后续把“正面可见”补为精确 `front` | 通用MCP输入Schema内联可展开引用并保留原校验；只传已确认粒度，独立形态无需占位；未知或受到换座位影响的旧事实省略；审计每次真实调用而非只看最后一次 |
| 事实选择实际支持的规则 | 缺资料场景针对沙发与床一起承诺后续形态计算，未说明沙发不受支持 | 描述中明确方向布局门/床/书桌/灶，形态床/书桌/灶；未知家具不改用途套入；用未见物体检验迁移 |
| 规则结果变成有边界的判断 | 年盘或玄空单独请求曾生成空八宅候选；原始盘 complete 易混成布局 complete | 技术修复限于所选层，并分别展示 requested/layout 状态；前端与评估按实际作用域和缺项读取，不平均多层 |
| 判断变成现实可行方案 | 工具匹配方向不承载“不能搬”“不能买镜子”“两人共用” | 将目标/约束放在咨询工作流，缺少无关约束不阻塞部分计算；行动需同时有规则依据和用户允许的实现条件 |
| 更正与试用形成闭环 | 旧位置、朝向、使用人容易被追加而非替换；修复后成功可能遮蔽前一失败 | 以最新确认重建受影响请求，用 trace/parent 连接；保留全程失败和额外发现步骤；未变解释不重复计算 |
| 评价证明真实产品能力 | 手工结构化探针直接命中正确规则，不检验模型发现、采集和事实提取 | 分开连接MCP直调、真实模型、进程内回归；不以词汇命中评分，自动核对参数，人工判断行动、事实与约束 |

## 真实模型体验与保留的失败

使用 `scripts/experience_codex_host.py`，用户配置模型 `gpt-6.1-sol`，咨询目录正常加载中等推理配置，没有指定模型或 effort。每类任务是独立临时会话、同一运行内共享 host；MCP 范围在子进程内限定为风水，未改用户全局配置。公开回复、调用参数和回执保存在 `consultation/fengshui-codex-experience/` 与 `consultation/fengshui-codex-transfer/`。这些是受控真实模型体验，不等于已有桌面连接的部署验收。

人工评审是逐项检查事实、规则依据、行动与约束，不是关键词评分。上述“通过”只指明表格中所列维度，整个流程存在失败的场景没有升格为全部通过。脚本记录中的源码 hash 和运行顺序须保留：第一批处于指引与核心修复过程中，第二批属于产品边界指引修复后、通用MCP inputSchema内联修复前；不能统一称作最终版本验收。

第三批新 host 在输入 Schema 修复稳定后启动，启动时的 `mcp_server_sha256` 保留；共享首轮字段投影优化随后落地，后面的朝向任务实际取得并使用嵌套投影字段，灶台任务仍用原建议字段。必须依据实际调用参数判定已消费的契约，不能仅按进程启动时间判断全部字段配置。不同对象与复杂度不是严格A/B，不据27.98s对53.14s宣称加速。所有回复完成也不代表调用全程无误，最终朝向重跑仍保留配对角色失败。

第四批新 host 在 Placement 的机器可见 `allOf`/`anyOf` 交叉条件修复后启动，采用此前未运行的床头自然语言场景。独立 required/forbidden 合同在查看模型输出前加入，不预设星值；参数审计两轮通过，人工核对规则输出、固定床位、撤回旧方向和未知项保留。该观测补充了角色从 desk 迁移到 headboard 的证据，未删除早期 desk 失败，也不证明模型以后永不漏参。四批合计10会话19轮，首次校验失败仍为3次。

自动证据审计结果保存在 `consultation/fengshui-journey-audits/`，它会暴露所有首次失败而非只看恢复后的末答。矛盾描述的更正轮初版合同要求可选 `entrance_position=front_left`，产生假失败：该轮已把前左事实保存于 evidence，三项被请求规则只需要可见/直线/背靠。已移除冗余必传约束，理由及原审计报告保留在 probes `contract_revisions` 和 `.reviewed-contract.json`；这是纠正把“多传字段”当能力的评价错误，未移除任何影响所请求判断的事实、禁止项或真实调用失败。

## 已落地的产品修复

1. 根目录与咨询目录 `AGENTS.md`、包内 MCP instructions、`docs/codex-guide.md` 同步目的、不可移动/转向/预算/多人约束、最新确认替换旧事实及 receipt 链。已有事实允许部分计算，不强制先询问所有约束。
2. 共享 `fengshui_assess` summary 与咨询指引明确支持对象；未支持家具不换成已支持用途。新增书柜/餐桌迁移检验，保留原沙发遗漏。
3. 独立形态不创建无方向 placement，观察只保留确认粒度；换座位后未确认的旧相对位置不沿用。
4. 体验脚本新增朝向更正、形态多轮/不可移动、多人冲突、年度边界、互相矛盾、未支持对象和灶台迁移。提示只有用户资料与意图，不包含评估器所期待的工具字段。
5. `consultation/fengshui-product-probes.json` 将独立 turn expectations 与8项连接MCP直调结果分层保存。expectations 只提供给证据审计，不进入模型提示。

不把预算/可搬性塞进风水效力算法，是为了保持规则与现实决策的来源边界：现有规则能够输出方向关系，咨询层才能结合用户意图筛候选。若未来实现几何布局，应另建可验证的几何输入和碰撞/通行约束，不以方向列表冒充可移动性。

## 防止奖励投机的验收要求

- 自动审计真实 `mcpToolCall.arguments` 的 required/forbidden 路径；缺参数证据标 insufficient，不从答复猜调用；首次失败、恢复重试、额外发现成本全部保留。
- 对缺资料、矛盾和未支持任务，合理澄清或明确未覆盖可以是正确行为，不能奖励“调用更多”或“永远给方案”；部分事实可算时也不能一律停在澄清。
- 人工核对每条行动与已确认事实、返回 rule/source、允许的现实约束，及更正后的撤回；提到免责声明不等于没有作出错误承诺。
- 覆盖门/床/桌/灶、未支持对象、多住户、候选出生规则、测量/照片候选、位置/面对独立、不同年份、未知项和改口。变换姓名、日期、方向、对象和约束，期待由计算派生，不能固定命中某case数值。
- 隐藏待评估变体并固定修复前后边界；任何人工添加合同需标 review 前置时间及未覆盖维度，不能看结果后只补通过项。
- 记录首次成功答复时长、失败调用、发现资源和字节体积；不把 engine duration、连接调用 latency 与模型完整轮次耗时混为一项。

## 证据范围

已验证的是已连接工具的规则分层行为、真实配置模型若干自然语言多轮的事实提取/调用/答复、以及文档与共享指引修改。Linux/Python3.12 golden、所有跨传输回归、生产桌面连接刷新和实际住宅实测不是这些模型记录自动证明的内容，应分别看主验收记录。

来源可追溯证明采用的规则版本，跨端一致证明实现一致；没有测试证明具体物件、传统名称或布局能够改变健康、财富、工作表现。产品要交付的是可解释、可复核、有约束的传统规则咨询。
