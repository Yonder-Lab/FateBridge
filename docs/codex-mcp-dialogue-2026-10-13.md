# Codex MCP 与真实对话验收（2026-10-13）

已完成实际接入与五类多轮对话：Codex 能自动选取相关工具，先补齐出生时间，再计算并解释；无户型/朝向时先询问，不猜方向。发现的接入版本错配、发现负担、格局文案矛盾和分数口径不清已修复。宿主额外探索和真实模型延迟仍有波动，不能把这轮验收称为所有场景都已流畅。

## 验收环境与证据边界

- 使用桌面版自带的 `codex-cli 0.162.0-alpha.17.2` 原生 `app-server --stdio`，已登录账号的 `gpt-6.1-sol`、high 推理强度。
- 从仓库外临时目录创建 `ephemeral=true` 多轮对话，保留现有插件、MCP 和模型设置。问题使用普通中文，不预置工具名称或答案；后续用户输入只补充资料或追问。
- 自然语言咨询与 MCP 进程均真实运行，不是 Mock、单纯协议模拟或另一套模型 API。没有点击桌面聊天界面，也没有重载当前根聊天。
- 已保存 `mcp_servers.fatebridge`，使用仓库 `.venv/bin/python` 的绝对路径，两个筛选变量为空。保存配置后的事业与缺失时间案例实际发现 **87 个工具**，没有进程级 FateBridge 配置覆盖。
- 注册前后逐项比较解析后的其他 Codex 设置并恢复 CLI 自行省略的空参数数组。用户模型和其他服务保持原值。原配置备份只保存在用户配置目录，未进入仓库。
- 所有人物资料均虚构；分析日期固定在 2026-10-12，以区分日期解析与测试运行日。

证据见 [validation.json](audits/2026-10-13/codex-mcp-dialogue/validation.json)、[注册回执](audits/2026-10-13/codex-mcp-dialogue/registration.json) 和 `final/` 中各案例。记录保留公开回答、实际 MCP 参数/结果和宿主活动状态，省略推理流及宿主后台命令的本地文件内容。

## 实际发现与修复

### 1. 桌面 CLI 与 PATH CLI 不一致

PATH 的 `codex-cli 0.142.5` 宣告的模型清单与本账号实际可用模型不一致，调用返回“不支持该模型”。桌面版原生 CLI 可以正常运行用户已配置的模型。

`doctor` 现在优先读取可执行的 `CODEX_CLI_PATH`，返回 `codex.cli` 来源，并在注册命令里使用该 CLI 的绝对路径。不再通过改用户模型来绕过版本错配。已测试桌面路径、含空格路径及不可执行路径的回退。

### 2. 缺资料时过早读取大契约

基线缺出生时间的第一轮先进行了五次 MCP 发现/契约读取，45.37 秒后才询问。初始化指令现在要求先一次简短追问，禁止补零点、借用演示资料或沿用确定时刻的结果；无户型/朝向时也先补资料。

最终已注册连接第一轮没有业务调用或完整契约读取，25.07 秒后询问时间；补充 10:30 后正确调用，随后“只知道上午”的追问明确撤回确定时刻假设。该小样本只证明行为修正，不构成延迟改善承诺。

### 3. 首轮发现与输出负担过大

新增 `fatebridge://tools/{tool}/input`，与 CLI `describe --detail input` 共用描述函数。保留输入 Schema、顶层输出字段和完整输出契约链接，提供经过严格投影实调用验证的 `suggested_fields`。12 种首轮投影视图由打包数据统一提供，体验脚本也读取同一来源。

四种常用工具的描述字节数由 22–39 KB 降至 8–12 KB；完整 Schema 仍可按需读取。真实 Codex 已采用新输入资源、`strict_fields=true` 和精简结果。初始化指令同时规定后续调用沿用真实回执的 `trace_id`，用前次 `run_id` 作为 `parent_run_id`；最终事业、时运、财运及合盘调用均实际串联成功。

### 4. 解读中的文案与口径矛盾

事业结果曾同时出现“75 分、中等格局”和“事业格局高”的子项文案。修为“官印相生，为事业格局加分；总体层级以综合评分为准”，不改变数值、阈值或计算算法。

合盘基线把传统净分 +8、其“非常匹配”标签与另一个 39/100 维度理解为内部矛盾。现在三处分别返回 `score_basis`：

- `summary`：多维加权的 0–100 分。
- `traditional_compatibility`：合冲刑害加减净分，0 为中性，其等级只评价这个净分。
- `detailed_analysis.traditional_analysis`：从 50 起按摩擦规则扣分的独立 0–100 维度。

最终真实追问能够解释这些口径，明确“非常匹配”不能代表整段关系，也不能平均分数或当成功概率。旧等级标签保留以维持兼容；计分依据随数据和中文快照输出。两份 Golden 的展示迁移逐项确认原有数值叶子不变。

## 对话验收结果

| 用户情境 | 实际行为 | 验收结果 |
| --- | --- | --- |
| 换工作并考虑生意 | 自动调用事业、时运、财运，明确共同依赖八字；追问辞职时区分可复算计算、传统规则和现实建议 | 通过，保存配置的全量 87 工具连接 |
| 出生时间未写 → 10:30 → 其实只知上午 | 先追问；正确保留日期、小时和分钟；后来拒绝沿用确定时间盘 | 通过，保存配置的全量连接 |
| 2 月 30 日 → 更正为 5 月 15 日 | 拒绝无效日期并要求更正，随后使用更正数据分析 | 基线与较早复测通过；最后额外补跑遭遇下述宿主连接失败 |
| 双人关系与分数追问 | 自动选双人配合度、关系星盘，未混入无关工具；依据返回相位解释并区分计分尺度 | 通过，缘分场景的 10 工具连接 |
| 沙发/床布局无朝向或户型 | 未排宅盘；询问户型/尺寸/北向，将一般居住建议与传统规则分开 | 通过，风水范围的 7 工具连接 |

多轮对话中没有人工指定工具，也没有替用户静默回答客户端输入请求。字段投影均有效，工具结果成功，后续调用使用真实运行凭据。人工解读复核与参数/凭据自动检查共同构成验收证据。

## 回归与仍需注意的体验边界

- 固定副本全量测试：**1940 passed、89 skipped、7 warnings**，约 256 秒；当前 `src` 源码与测试副本逐文件一致。
- 定向契约/体验测试：**93 passed**；Black、isort、mypy 和 `git diff --check` 通过。独立 stdio、CLI、本地 REST 体验脚本再次返回 `ok=true`。
- macOS 跳过的 89 项包括要求 Linux 运行环境的 Golden，不能据此声明本轮已完成 Linux CI。保留展示迁移的数值不变回执。
- 当前 Codex 的高优先级全局指令触发记忆与工作目录查询。FateBridge 已提示直接使用已连接 MCP，但无法覆盖宿主指令；这些额外命令仍可见，测试资料没有借此补全。
- 完整事业/合盘首轮约 98–119 秒，普通追问约 8–31 秒。一次中间复测的无效日期回复耗时 **305.55 秒**，当时没有 FateBridge 业务调用。不能把所有等待归因于计算服务，也不能承诺当前体验已无延迟问题。
- 最后使用保存配置额外补跑无效日期案例，原生 Codex 反复报告 `Reconnecting`，最终在 **208.62 秒**返回 `workspace routing discovery timed out`；没有任何 FateBridge MCP 调用。这轮不计为通过，也未用以前的成功掩盖失败。[失败记录](audits/2026-10-13/codex-mcp-dialogue/host-failures/registered-invalid.json)与[宿主日志](audits/2026-10-13/codex-mcp-dialogue/host-failures/registered-invalid.txt)保留了证据；无法通过 FateBridge 计算代码修复该宿主路由错误。复现脚本现在保留宿主错误事件和超时前的公开活动。
- 另一次中间阶段的重复风水测试达到本地六分钟期限，旧脚本直接抛出超时，未保存未完成轮次。[超时回执](audits/2026-10-13/codex-mcp-dialogue/host-failures/intermediate-fengshui-timeout.json)与[日志](audits/2026-10-13/codex-mcp-dialogue/host-failures/intermediate-fengshui-timeout.txt)单列；无法从未保存活动推断其工具行为。当前脚本已修复超时记录遗漏，正式风水成功案例仍单独保留。所有运行阶段概览见 [all-runs-summary.json](audits/2026-10-13/codex-mcp-dialogue/all-runs-summary.json)。
- 全量连接完成了自动选工具验收，场景连接也分别验收。未逐一进行 87 个工具的真实模型咨询，未覆盖所有用户措辞，也未证明未来每轮一定选到相同工具。
