# FateBridge + Codex 风水布局根因审查与验收

2026-10-14。产品、技术、Harness、性能和独立评估五个方向分别审查、交换复现证据；协调者汇总修复并做跨端与隔离环境验收。所有人物和布局资料均为合成体验资料。

## 交付的本质

布局咨询应把用户确认的事实转成选定规则的判断，再在用户允许的调整范围内给出一项可行候选。计算正确、模型说得完整、出现免责声明、响应 `complete` 都不能单独证明咨询成功。规则正确性与现实健康、财富或工作效力是不同问题，本轮没有住宅干预实验，也没有建立预测效力证明。

## 根因和通用修复

| 环节 | 根因 | 已落地处理 |
| --- | --- | --- |
| 描述→事实 | 未知位置、相对入口和面对容易混同；用户换座位后旧观察容易被追加保留 | 共享咨询指引保留确认粒度，用户改口替换旧事实，独立形态不构造空 `placements`；未知不是 false，也不是默认时刻 |
| 事实→调用 | 原生 MCP 的嵌套 `$defs` 在宿主代码表示中可能呈现为 unknown；跨字段依赖原来只在 validator/文字里 | 通用内联输入 Schema，保留输出与运行时校验；Placement 的方向至少一项、朝向/角色配对及四用途角色约束发布为机器可读合同，同一映射供 validator 使用 |
| 调用→判断 | 未选八宅仍生成空八宅建议；原始盘完成掩盖布局未完成；元素候选丢失身份 | 建议限于已选方法，分别输出请求/布局覆盖状态及缺项，保留宅/人、性别候选、方位与作用域 |
| 判断→行动 | 方位匹配被当作可搬动结论；未支持家具可能被套进已有用途 | 明确方向对象门/床/桌/灶、形态对象床/桌/灶；目标、搬动、转向、预算和共享使用约束在咨询层核对；无可行调整就保留权衡，不用摆件保证覆盖问题 |
| 输出→体验 | 每个家具重复扫描全体八宅结果；首轮重复关系和来源详表挤占上下文 | 按对象索引结果；通用嵌套首轮保留依据、候选、分歧、缺项、作用域及限制，五行关系和完整来源按问题再展开 |
| 体验→评价 | 只核对几个参数路径或末次成功，可能漏掉伪造对象、额外错误工具和无响应；过度要求可选字段又会制造假失败 | 强化真实调用证据审计，保留每次失败和恢复；共享参数验证、允许工具与完整对象合同；人工另核对事实→规则→行动，自动门控不输出咨询成功率 |

## 真实模型证据与反奖励投机

使用用户配置的 `gpt-6.1-sol / medium`，没有覆盖模型或全局配置。四批共10个独立会话、19轮，覆盖9类任务：资料缺失、形态观察、不可移动/不可添镜、朝向纠正、多人共享冲突、年度作者规则、矛盾描述、未支持家具、床/灶迁移。

最初记录保留空 placement 和两次漏朝向角色造成的调用失败，以及未说明沙发不受支持、换座位后多推具体入口位置的问题。部分调用后能自行恢复，不将恢复视为首轮通过。独立评估还发现旧 Harness 的四种错误通过，已转成故障注入回归。

增强审计保存10段对话的19轮结果，14轮调用证据通过、5轮未通过；这不是咨询成功率，人工答复核对与调用门控分别记录。未知镜面关系被补成 false 等问题同样保留，不因原始答复最终可读而放过。

机器可读跨字段合同发布后，未使用过的床头场景两轮首次调用均成功，正确执行西南→南的更正、撤回旧判断并保持未知宅向/床位/出生时刻。首轮仍读取输入契约，不能据两个样本声称整体成功率或用户时延已改善。灶台迁移也保留“不强加背靠、不把旋钮当火门、不可添镜”的边界。

合同和原始记录分离，不把预期参数、星名或答案喂给模型；修复前失败不覆盖。可选入口方位没有参与所选规则时不强制传入，修正过严合同的理由与原审计保留。所提供自动证据检查主要是回归审计，不能作为未经独立取样的整体产品成功率。

详见[产品审查](fengshui-product-review.md)、[真实探针与合同](../consultation/fengshui-product-probes.json)以及 `consultation/fengshui-codex-*` 原始记录。

## 性能与作用域

22类请求覆盖资料部分、不同方法、不同对象数量及多人压力。通用首轮输出字节减少约9%–44%；50住户压力仅约2.86%，共享冲突依据完整保留。200对象下，被索引替换的布局子步骤配对测量约14.40→9.60毫秒，完整结果严格相等。这是局部运算改善，不是模型等待同比改善。

SDK 在小请求上重复检查输出 Schema 是主要本地协议成本；本轮没有通过关闭验证换速度。最后跨字段约束版本，87工具同一当前模型的引用发布/内联发现体积为2,051,658→2,051,664字节，所有输出 Schema 指纹相同；`fengshui_assess` 输入为12,366→12,719字节。参见[性能报告](fengshui-performance-review.md)和[最终发现合同比较](audits/2026-10-14/fengshui-input-schema-final.json)。
