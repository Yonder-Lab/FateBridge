# FateBridge 工作方式

按用户请求区分任务：开发、安装、排错、代码审查与验收按工程流程处理；排盘、事业／关系／时运咨询及结果解释按咨询流程处理。

## 用户咨询

### 资料与调用

- 使用当前聊天已确认的资料。人物资料完整的独立咨询是自包含任务，不查仓库、项目历史或记忆；用户明确要求沿用历史资料时再核对。
- 按所选计算一次核对必要资料；缺失或日期无效时用 1–3 句简短追问，不先写排盘计划。八字／紫微缺出生时刻不能猜，仅有时段时保留排盘不确定性，也不能把接口默认值或示例当作用户资料。命卦支持 `birth_date`，非立春当日无需出生小时；双人关系类型未说明时用 `general`。
- 按问题选择一项主证，必要时补旁证。专项分析已自动推算大运／流年，不重复计算已有结果。

| 咨询问题 | 场景技能 | 首选计算 |
| --- | --- | --- |
| 事业、换工作、创业、财运 | [onda-shiye](skills/onda-shiye/SKILL.md) | 事业用 `bazi_career`，财运按技能选择 |
| 姻缘、桃花、双人相处 | [onda-yuanfen](skills/onda-yuanfen/SKILL.md) | 双人用 `two_person_compatibility`，单人按技能选择 |
| 综合时运、大运流年、择时 | [onda-shiyun](skills/onda-shiyun/SKILL.md) | `timing_analysis` 或所选体系／粒度 |
| 传统健康文化、身心养护参考 | [onda-jiankang](skills/onda-jiankang/SKILL.md) | 按技能选择；具体不适优先现实求助 |
| 单项性格、天赋、学业、六亲 | [onda-mingge](skills/onda-mingge/SKILL.md) | 按具体问题选择专项或命盘 |
| 西占本命盘、流派盘、关系盘 | [onda-xingpan](skills/onda-xingpan/SKILL.md) | 按流派与盘型选择 |
| 起卦、具体决定、问事 | [onda-zhanbu](skills/onda-zhanbu/SKILL.md) | 按问题与起卦方式选择 |
| 明确要求多维度、八字紫微西占全面画像 | [onda-zige](skills/onda-zige/SKILL.md) | 三体系对照，保留缺失层 |
| 风水空间、布局与物件 | [onda-fengshui](skills/onda-fengshui/SKILL.md) | 布局主入口 `fengshui_assess` |

- 先读取匹配的场景技能再计算；已有工具合同不替代技能的解读规则。单项性格与全面画像按用户范围区分，不为完整画像误选单项技能。技能从软链接入口发现时，先解析 `SKILL.md` 的真实路径，再以真实目录解析引用；共享资料路径不能按 `.agents` 的父目录拼接。

- 下方生成合同已覆盖的工具，资料齐全且连接公开时直接调用。其他工具以已连接 MCP 的实际 Schema 和描述为准；需检索时按工具名限定 `ALL_TOOLS`，一次取得完整说明与参数定义后计算。只有选择确有歧义时才展开候选，不先列工具名再重复检索。
- 使用已验证的首轮 `fields`，设置 `strict_fields=true`、`include_snapshot_text=false`。完整契约、全年时间线及其他分支只在问题需要时展开。
- 用户明确要求完整 JSON、全部时间线或完整文件时，首次调用 `fields=null`，保留默认响应预算，再从 `result_delivery` 读取同一 run；精简首轮字段不适用于完整导出，不能先投影摘要再补算全文。

### 解读与后续

- 首轮先回答要点，给 2–3 条实际返回的依据和一项现实建议，通常约 200–300 字；详细请求按需展开。技术回执留在工具结果，精度限制与警告须说明。
- 区分计算结果、传统规则和现实建议。分数不是成功概率，个人内部结构不能直接解释为双方互动，“引擎非近似”不证明预测有效性；不替用户决定辞职或关系成败。
- 用户更正资料时替换旧事实，重建受影响输入并沿用 `trace_id`／`parent_run_id`；只解释未改变的结果无需重算。

### 风水空间咨询

- 使用独立 [onda-fengshui](skills/onda-fengshui/SKILL.md)，先读其[咨询闭环](skills/onda-fengshui/references/consultation.md)，再按问题读取来源与规则资料。普通收纳和工程任务不触发该咨询技能；布局、形态、桌面物件与行动状态的细则以该技能及其引用资料为准。
- 主要方法为九宫飞星、金锁玉关、八宅。局部工位／合租先考虑飞星、次金锁，八宅按独立个人命卦加入；采用[2026-10-15 用户专家访谈政策](docs/fengshui-expert-policy.md)并保留实际规则版本。核对 `priority_review_status` 与未选原因，已选层 complete 不代表优先方法全审；显式排除的方法不追补资料。BTB 仅用户明确另选，不作为默认主法或无方位替代。
- 布局主入口设 `analyze_layout=true`，只传已确认事实，保留缺失层与部分结果。位置、朝向、宅向、对象使用人各自核对；照片是候选观察，现状与行动约束分别记录，不能由目标或许可补出物理条件。
- 定宫先确认参考北、户型旋转／偏移、立极与分宫；无方位先审明确厨卫关系、形态、材质器形事实，不由个人命盘补宫，也不编造未有判据的“绝对禁忌”。环境五行与本人／周围人的八字紫微喜忌隔离，八宅命卦独立；年盘不能冒充历史宅盘。
- 本轮厨卫／床灶／镜面／梁管／尖角按 `interior_relations` 的明确两端、角色与有来源 predicate 审查；材质器形用 `material_facts` 独立保存，不以器形或资格推摆位。实际提交对应输入才读取 `interior_analysis/material_analysis`；照片 true／false均候选，未知不当已否定，搬转任一端均重核关系。作者异议分列，不包装成古典普遍禁忌。
- 家庭人物对应按已确认辈分／排行，本版本妻随夫序须显式确认；双身份保留多宫，生肖独立确认，本宫主、对宫次，环境象征索引不当八宅命卦。只解释象意用 `household_scope=symbolic_reference`，不绑实际方向或追罗盘；关联环境用默认范围。多层逐层核对独立中心及共用方向，院落／绿化归第一层；`subject_ids` 未列某人不等于不使用，负向排除须相关空间 `usage_confirmed=true` 与证据成对。本层局限且异层适宜有依据时不自动外推局部不利，仍复核共享影响。拱门／开放厨房低优先适度提醒。
- 按请求说明个人匹配、形态、宅／年盘及显式另选桌面作者规则的实际覆盖。象意、现代职业／家具类比与实际判定规则分别说明；命卦不等于八字喜用，不同方法不能宣称补偿或抵消。每项建议须关联事实、规则、作用域与执行条件，未确认可行的候选不写成可立即执行；无规则的物件明确保留范围，生活建议单独标明。
- 所有风水解读保留 `rulesets`、`rule_trace`，最终答复注明本次作者／版本及来源标题或链接。追踪已解决、待确认及未覆盖项目，完整审查和逐物件请求不受首轮字数限制；验收按规则与事实核对，不要求特定摆法、搬动物件或更多建议。

## 工程任务

- 检查当前源代码、适用历史、共享契约及相关测试，保留用户已有改动。
- 修改共享计算或跨传输契约时，验证 REST、MCP、CLI 的一致性；真实模型对话、本地测试及实际环境验收分别报告。
- 咨询首轮的简短输出要求不适用于开发、根因分析或完整验收报告。下方合同由脚本生成，接口变化时重新生成并运行 `--check`，不手改生成区。

## 已核对的常用 MCP 调用合同

此段由 `scripts/build_codex_call_contracts.py` 从实际 MCP inputSchema 与共享首轮字段生成，只删标题和说明，保留全部参数、默认值、必填项与约束。更新接口后重新生成，检查模式用 `--check`。

下面五项工具已具备调用所需定义。对应计算的资料齐全且工具在连接中公开时，直接调用 `tools.mcp__fatebridge__<tool>(参数)`，无需先检索或打印 ALL_TOOLS。如需确认公开范围，可在同一次 exec 中检查 ALL_TOOLS 的名称并调用，不另起发现往返。合同未覆盖的工具或参数疑问再读取实际工具定义，不猜测。

使用用户已确认的资料，不把接口默认值当成用户已提供的出生小时。这些出生接口使用公历，农历资料需先正确转换。出生日期/小时使用 birth_*（双人分别 person1_/person2_），分析日期使用 analysis_*；as_of 是带时区的 ISO 时间，仅冻结未显式指定的当前时间。性别接受男/女等已确认写法；出生时区是 IANA 名称或 UTC 偏移。太阳时默认开启；仅按用户明确要求关闭。未知经度可省略，以返回精度说明限制，不能猜经度。中式出生工具不传 birth_latitude；西占推运需要经纬度，并以 analysis_hour/minute 指定目标钟时。未指明双人关系类型用 general，不要自行传入大运/流年柱覆盖自动计算。结果仍按实际返回字段、精度和回执解读。
